# 3D character creator

## Open and use

New student onboarding opens `StudentAvatarSelect`. Existing students can use **Profile → Edit Appearance**. For a direct Unity preview, select **Imagine Quest → Character → Play Creator**.

The creator shares the student hub's cabin art, pirate lettering, warm brass/brown buttons and hover/click sounds. It uses a short entrance fade, subtle background motion, keyboard focus feedback and a coalesced model transition that settles on the latest choice when several options are selected quickly. Appearance names are not repeated in a footer.

Choose Boy/Girl, one of six skin tones, four hairstyles per body, and six hair colours. Boy styles are Bald, Crew Cut, Side Part and Coils; girl styles are Bald, Short Curls, Long and Twin Buns. Labels update when switching body. Drag the model or use Turn Left/Right; scroll to zoom, use Walk/Idle to inspect animation, and Reset View to restore framing. Each model always wears its basic deckhand uniform. Confirming saves the selected appearance; reopening restores those choices. Profile and dashboard show a live 3D headshot. The ship uses the same prefab, mesh, hair and material settings with the existing movement controller.

## Persistence and compatibility

New appearance selections use a strictly validated string in the existing `users/{uid}.avatarId` field: `pirate-v2:<body>:<skin>:<hair>:<colour>`. All 288 offered combinations round-trip. `pirate-v1` saves retain their body, colour and original hairstyle: compatibility-only fitted meshes preserve old cross-body hair choices. Loading a profile never rewrites it. Missing or malformed IDs render a clothed default and are upgraded only when the student confirms. The existing `characterColor`, `characterClass`, `avatarChosen`, and `updatedAt` fields are updated together; the creator does not replace the profile document or alter its creation date, rewards, progress, classes, Hearts, or XP.

Authenticated saving uses the project's existing Firebase client and existing profile rules. No backend deployment, new cloud service, security-rule change, billing-plan change, or paid dependency is part of this feature. Guest play saves a separate local appearance. Guest settings are never applied to a signed-in account, and cached signed-in settings are scoped to their owner.

The UI waits for the profile before enabling save. Failed loads offer Retry; failed saves keep the current choices. Saves are single-flight and freeze appearance controls until completion. Account changes and abandoned screens invalidate asynchronous UI responses. A slow write shows a connection message and leaves Back available; it can still finish saving to the original account after leaving the screen.

## Verification

`StudentAppearanceTests` validates every encoded appearance and malformed/legacy fallbacks. `StudentCharacterCreationTests` checks both clothed Humanoid models, all hairstyles, animated walking, complete material slots, independent clothing/skin tint, selection limits, preview controls, portrait isolation/lifecycle, save retries, duplicate clicks, missing profiles, account changes, leaving during a pending save, and appearance/mesh consistency on the ship.

Verified on 15 November 2026: the feature's initial full validation passed 51 Edit Mode checks and all 15 existing workshop, portal, arrival, quest-menu, Hearts/XP and combat-return checks. All 16 appearance-data checks passed after the neck/hair revision. On 16 November, the final collar repair passed all 10 creator/geometry checks in the editor and all 10 in the standalone Windows player. Both bodies were rendered at 1600×900, 1280×720 and 1024×768. Inspection covers 128 head/hair views (eight offered body/style combinations, four angles and four animations), 96 elevated collar views, and both bodies on the actual ship. Reports and renders are saved outside Assets so they are not imported or shipped with the game.

Direct ship previews now initialize the existing Firebase login and refresh its appearance even without a class context. An unverified default body is hidden while the account resolves; an account-matched cache can display immediately after authentication initializes. Profile loading refreshes the same account-scoped cache used by gameplay. Late responses from an abandoned request or another account cannot replace the current body. The Play Mode fixture explicitly restores a saved girl after direct entry without a class, checks a switched-account response is ignored, and verifies failed reads preserve the displayed character. **Imagine Quest → Character → Play Saved Character on Ship** opens this path for manual checks.

The generated head has a continuous, capped neck extension beneath the collar. It is narrowed inside the uniform and weighted to the neck/spine rather than the shoulders, closing the gap left by the former head-weight cutoff. Exposed arm skin uses the head's sampled neutral tone instead of an incompatible full-body texture atlas. Hair vertices are projected outward against each body's actual scalp at build time; each fitted mesh follows the Head bone. Curls use an underlying fitted shell and a hairline derived from the eyes' face direction.

The collar opening is wider than the neck. A separate upper-chest skin mesh now joins the neck to the garment's exact open neckline, including the boy's front slit. It extends beneath the trim and blends neck/spine weights into the original collar's weights, so it follows movement without exposing the shirt's interior. The regression check probes inside four measured, animated garment-rim vertices against the actual head and chest surfaces. A control repeats those probes with only the head, requiring the missing collar surface to be detected on each body; this prevents a head covering the entire test area from hiding a regression. It renders both bodies from four directions at 15°, 45° and 70° elevation during idle, walk, run and jump: 96 additional collar views. Baseline renders and the initial failing report are retained in `Temp/CharacterVerification/CollarBefore`.

The Character menu includes Verify Character Data, Verify Character Models and Verify Windows Characters. These use isolated offline test profiles, restore the prior test environment/build settings, and save reports under `Temp/CharacterVerification`. `StudentCharacterGeometryTests` checks neck continuity on both bodies and all six internal styles during idle, walk, run and jump; ray checks reject hair obscuring either eye. It also captures all eight offered body/style combinations from four angles in each of the four poses (128 renders) for visual inspection. No test writes a production student profile.

`firebase/functions/test/appearance.integration.cjs` also passed against local Auth/Firestore emulators with the existing repository rules. It verifies the creator's exact profile fields plus server timestamp, preservation of creation date/username/role/Hearts/XP/currencies, saved appearance readback, and rejection of another account's reads and writes. It requires `GCLOUD_PROJECT` beginning with `demo-` and both emulator hosts on `127.0.0.1`; it refuses production endpoints. Run it through an isolated Auth/Firestore Emulator Suite with `npm --prefix firebase/functions run test:appearance`. No production profile was written during validation.
